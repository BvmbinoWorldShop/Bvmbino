OVERVIEW

What is Bvmbino Pro?

Bvmbino Pro is a personal AI assistant web app built as a single self-contained HTML file, deployed as a Progressive Web App (PWA) on Vercel. It operates as a multi-provider AI Chief of Staff — routing your requests across 7 different AI providers automatically, always trying the most powerful free-tier models first.

Core concept

BYOK Model Key Architecture
Users bring their own API keys. Keys are stored encrypted in the browser — never sent to any third-party server. Each user owns their own access.
Single-file PWA Tech
The entire app — UI, logic, security, AI routing — lives in one index.html. No backend. No database. Installable on iPhone/Android like a native app.
Multi-provider fallback Smart
If one AI provider fails or rate-limits, the app silently tries the next. Groq → OpenRouter → Cerebras → Mistral → OpenAI → Anthropic → Gemini.
Offline-capable PWA
Service worker caches the app shell. The UI loads even without internet. Connection state is shown via the robot's eye color (green = online, red = offline).

What Makes It Unique

🤖 3D Connection-Aware Robot
The robot mascot is a fully custom SVG with radial gradients, specular highlights, depth shading, and arm geometry. It's not a flat icon — it has a 3D appearance. More importantly, it's alive: it spins when the device is online (green eyes) and pauses when offline (red eyes). The eye color is driven by a CSS custom property --robot-eye updated in real time via JavaScript event listeners on navigator.onLine.
⚡ Free-First AI Routing
Most AI apps force you to pick one provider and pay. Bvmbino Pro automatically cycles through 7 providers in priority order, always hitting free-tier endpoints first. The try order is determined by which keys you've added — you only pay if free tiers are exhausted. This is transparent to the user.
🔒 AES-256 Encrypted Key Storage
API keys are never stored in plaintext. They are encrypted with AES-256-GCM using a PBKDF2-derived key from your personal passphrase (100,000 iterations). The localStorage only holds ciphertext blobs. Even if someone clones your browser storage, they see {"iv":[...],"ct":[...]} — not your actual keys.
🏗 Obfuscated Production Build
The npm run build pipeline extracts all inline JavaScript, passes it through javascript-obfuscator with hexadecimal identifiers, base64 string arrays, split strings, number-to-expression transforms, object key obfuscation, and self-defending code. The output is deployed to Vercel's dist/ folder. The source stays readable locally; production is protected.
📱 True Edge-to-Edge on iPhone
The app background extends behind the iOS status bar (top) and the home indicator (bottom) using body::before with bottom: calc(-1 * env(safe-area-inset-bottom)). The topbar is transparent glass (rgba(6,8,10,.06) + backdrop-filter: blur(28px)) so the gradient shows through behind the clock and signal icons. No black bars anywhere.
CHANGES MADE — SESSION LOG

Visual Improvements

Edge-to-edge background ✓ Done
Problem: Background gradient stopped at the viewport edge, leaving black bars behind the iOS status bar and home indicator.
Fix: Moved the gradient to a body::before pseudo-element with position:fixed and bottom: calc(-1 * env(safe-area-inset-bottom, 50px)). This extends the gradient physically past the viewport into the home indicator zone. The topbar was made fully transparent glass so the gradient shows behind the time/signal icons at the top.
3D Robot SVG ✓ Done
Problem: The original robot was a flat 2D icon with no depth.
Fix: Replaced with a fully custom 88×88 SVG featuring radial gradients for body depth, a gold visor with linear gradient, specular highlight dots on the eye lenses, a gold antenna ball with halo glow, arm sections with sheen reflections, and a face scanner bar. The robot logo in the sidebar was also updated to match.
Connection-aware robot state ✓ Done
Feature: The robot responds to network status in real time.
Online → eyes glow green + robot spins (CSS animation running).
Offline → eyes turn red + robot freezes (animation paused).
Implemented via CSS custom property --robot-eye + JS window.addEventListener('online'/'offline').
Pills flush to screen bottom ✓ Done
Problem: The three action pills (Memory, Web Search, PDF Export) had excess space below them, sitting visually high above the home indicator.
Fix: Reduced .inzone padding-bottom from env(safe-area-inset-bottom, 20px) to 4px. The body gradient already extends behind the home indicator, so the pills now sit at the physical screen edge for an immersive feel.

Functionality Fixes

PDF upload blank fix (PDF.js) ✓ Done
Problem: Uploading a PDF for AI analysis produced no text — the extraction returned blank.
Root cause: PDF.js v3.x deprecated disableWorker: true. Setting workerSrc: '' caused the library to silently fail on text extraction.
Fix: Set pdfjsLib.GlobalWorkerOptions.workerSrc to the matching CDN URL for pdf.worker.min.js and removed the deprecated disableWorker option.
PDF export blank/corrupted fix ✓ Done
Problem: Exporting a conversation as PDF produced a blank or corrupted file.
Root cause: The export function created an off-screen DOM wrapper with position:fixed; left:-9999px. html2canvas captured the actual screen at that coordinate — which is empty — not the wrapper's content.
Fix: Replaced DOM-element approach with html2pdf().from(htmlString, 'string'). The content is passed as an HTML string, bypassing the off-screen rendering bug entirely.
API fallback order corrected ✓ Done
Change: Reordered the AI provider try-sequence to hit free-tier providers first.
New order: Groq (free, fastest) → OpenRouter free models → Cerebras → Mistral → OpenAI → Anthropic → Gemini (last).
This ensures users consume free quota before spending paid credits.

Security Architecture

User enters passphrase
       │
       ▼
SHA-256 hash checked against localStorage['bv_gate_hash']
       │
       ▼
PBKDF2(passphrase, salt, 100000 iterations) → AES-256-GCM key
       │
       ▼
Decrypt all provider keys from localStorage['bv_enc_*']
       │
       ▼
_kv = { groq: 'sk-...', openai: 'sk-...', ... }  ← memory only
       │
       ▼
boot() → App.init() → API calls use getKey('provider')
What's protected Keys at rest are AES-256 ciphertext. DevTools Application tab shows only blobs. The app gate blocks access without the passphrase. Obfuscation protects logic.
Known limitation (BYOK by design) When an API call fires, the decrypted key appears in the network request's Authorization header. This is unavoidable in a browser-based BYOK model without a server proxy. Since users use their own keys, this is their personal responsibility — not a product security issue.
